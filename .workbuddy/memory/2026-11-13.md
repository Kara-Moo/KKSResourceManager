## 追加：预览修复 + 状态区域 + 移除工作室角色

### 用户实测发现的问题与修复
1. **PNG 预览无法显示** —— 原因是前端用 `file:///绝对路径` 加载，Wails v2 的 WebView
   安全策略拦截本地绝对路径。修复：新增 `preview.go`，后端解码 PNG → 缩放（≤320x400）
   → 合成白底 → JPEG(q82) → base64 data URI 返回，前端 `<img src="data:...">` 渲染。
   - 必须缩放：用户实际卡片有 42MB / 7.5MB 的，直接 base64 会拖垮 WebView
   - 新增 `GetCardPreview(path)` 绑定；用 `previewSeq` 序号防止快速切换时旧图覆盖新图
   - 路径白名单：只允许读 KKS_ROOT 与 DELCARDS_ROOT 内的文件
2. **状态区域** —— 位于「当前管理类型」之前，四态：
   - idle 未选择路径（红底黑字，进度条隐藏）
   - loading 正在加载（红白闪烁 1s，蓝色进度条，zipmod/资源两阶段各占 50%）
   - error 加载错误（红底黑字，进度条中止变黄）
   - done 扫描完成（黑底白字，进度条消失，文案由后端生成）
3. **移除「工作室角色」** —— 不再扫描 `UserData/Studio/character`，
   不创建 `DEL-studio_char`，前端下拉框同步移除。

### 重要的环境适配决策
用户真实目录 `E:\KKV114` **没有** `UserData/coordinate/male`（也无 Studio/character）。
若把全部资源目录设为必需，会导致程序直接报「加载错误」而完全不可用。
因此区分：
- `RequiredDirs`（缺失即报错）：chara/female、chara/male、Studio/scene、Studio/pose、coordinate/female、mods
- 可选目录（如 coordinate/male）：缺失只导致该类型列表为空

### 顺带修复
- 「重新扫描」按钮原本只刷新列表、根本没触发重扫 → 新增 `Rescan()` 绑定真正重建依赖图
- `ScanAll` 进度回调改为携带阶段名（zipmod/resource），进度条才能反映真实进度

## 追加：交互增强 + 自由修改模式 + 隐藏文件夹（第三轮）

### 新增文件
- `invisible.go` —— 空文件夹隐藏索引与路径重建
- `clipboard.go` —— 复制/剪切/粘贴
- `preview.go` —— 缩略图（第二轮已加，本轮扩展 GetFolderPreview）

### 隐藏文件夹机制
状态存于 `DELCARDS/DEL-invisible/`：
- `KKSinvisible.json` / `DELinvisible.json` —— 被隐藏的文件夹（相对各自根的路径）
- `OriginKKS.json` / `OriginDEL.json` —— 原始目录树（只记文件夹，不记文件）

关键设计：隐藏的是**目录树**而非单个文件夹，因此恢复时能把整棵子树还原。
隐藏前校验递归文件数为 0，否则报「无法删除，不是空文件，存在 N 个文件」。
`EnsurePathForOperation()` 在隔离/恢复前检测父目录是否被隐藏删除，是则重建。

### 关键安全决策（重要）
1. **zipmod 以扩展名判定，而非 GUID 是否解析成功**。
   若按 GUID 判定，manifest 解析失败的 zipmod 会绕过依赖检查被移走 → 造成依赖缺失。
   现在 GUID 为空时**保守拒绝**移出并提示「无法识别 GUID，无法确认依赖关系」。
2. **zipmod 的「复制」语义等同移动**：从 mods→隔离区是隔离（源必须移走），
   从隔离区→mods 是启用。否则「复制到隔离区」等于没隔离，源还留在 mods 里。
3. **同名冲突整体取消**：粘贴时预检全部目标，任一冲突则整个操作取消并报「无法复制」。

### 交互变更
- 点击行 = 只切换焦点（不勾选）；焦点行浅蓝底 `.is-focused`，长名换行完整显示
- 非焦点行长名截断（CSS text-overflow: ellipsis，max-width 320px）
- 勾选文件夹级联勾选全部子孙（`collectDescendants` 按 path 前缀匹配）
- 文件夹焦点时右侧显示统计 + 2x2 窗格（最多 3 个子文件夹 + 1 个「还有 N 个」）
- 模式切换按钮：自由修改模式(红) / 安全加载隔离模式(绿)
- 右键菜单：自由模式=复制/剪切/粘贴；安全模式=隔离(左)/启用(右)
- 新增管理种类「隐藏的文件夹」，其下隔离/启用按钮禁用，显示恢复按钮

59 个测试通过 · `go test -race` 干净 · 真实目录 E:\DELCARDS\DEL-invisible 下
四个状态文件已自动创建并格式正确



## v2 重构规格书（本次工作）

用户反馈 3 个硬 bug + 5 个设计问题，要求产出一份"一次性成功"的工程提示词。已写
`docs/v2-重构提示词.md`（1334 行），含红线、缺陷根因（带行号）、目标架构、增量索引、
事务引擎、插件依赖、UI 规格、API 契约、验收清单、分阶段计划、反模式黑名单。

### 定位到的真实根因（重要，后续要修）
- 单击无反应：`frontend/index.html:734` 的 `const hideBtn` 在 if 块内，`:751` 的
  `div.onclick` 在块外引用 → 每次点击抛 ReferenceError，`setFocus` 永不执行。
- 右键菜单消失：行 handler 打开菜单后事件冒泡到 `:926` 的 document contextmenu
  监听，`!elContextMenu.contains(e.target)` 成立 → 立即 hide。
- 隐藏文件夹恢复失败：`app.go:868` 节点 ID 用绝对路径，`invisible.go:397` 把入参当
  相对路径匹配 → 必然"未找到隐藏记录"。
- 根目录全选变灰：`:617` 只统计 `n.type !== 'folder'`，纯文件夹目录时 length=0 → disabled。
- 依赖图污染：`clipboard.go:322` 反向 append 无去重，重复移动后引用数虚高。

### 关键架构决策（写进规格书）
- 索引只持久化正向数据，反向图每次 `derive()` 派生，禁止双写。
- 破坏性操作全部走 Tx（预检→计划→执行→journal 逆序回滚），崩溃启动自动回滚。
- 删除 = 移入 `_trash`，不做真删；移动不预复制（journal 即可逆），避免 40GB 备份。
- 状态文件/索引/缩略图缓存全部放 `DELCARDS/_state`，绝不写 KKS_ROOT。
