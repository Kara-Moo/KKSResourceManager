## 1. FIX-01 缩略图队列从未启动（P0，影响最大）

### 1.1 现象

右栏所有格子停在骨架态（截图里那个浅灰底 + 小图标），等多久都不出图；`thumb:ready` 事件从未到达前端。

### 1.2 根因链（三段，缺一不可）

```
startup()                  → a.manager == nil  → StartThumbQueue 不执行
SelectKKSRoot()            → a.manager = manager（新实例）→ 没有启动队列
BuildPanel → thumbRequest  → m.thumbs == nil → return "", pending=true
```

`panel.go:428`：

```go
if m.thumbs == nil {
    return key, "", true      // 永远 pending，且任务根本没进队列
}
```

注意最后一句：**不只是"没有 worker"，而是任务从未入队**。所以即便事后补救启动队列，也必须重新请求面板。

### 1.3 修法（三处，都要改）

**（1）`SelectKKSRoot` 里，`a.manager = manager` 之后、`startScan` 之前：**

```go
// 切换根目录：先停掉旧队列，避免旧 worker 继续为旧根生成缩略图
if old := a.manager; old != nil {
    old.StopThumbQueue()
}
a.manager = manager

// 关键修复：Manager 是这里才创建的，队列必须在这里启动。
// startup() 里的那次调用是针对"已存在 manager"的幂等兜底，
// 不能作为唯一路径 —— 那是本 bug 的成因。
if err := manager.StartThumbQueue(a.notifyThumbsReady); err != nil {
    a.emitLog("warn", "preview", "缩略图队列启动失败："+err.Error())
} else {
    a.emitLog("info", "preview", "缩略图队列已启动（3 worker）")
}
```

**（2）`startup()` 里的那次调用保留**（`StartThumbQueue` 已幂等：`m.thumbs != nil` 直接返回）。

**（3）队列启动成功后，主动让前端重取一次面板**（否则已经渲染的格子还是 pending）：

```go
wruntime.EventsEmit(a.ctx, "panel:invalidate", map[string]interface{}{"reason": "thumb-queue-started"})
```

前端 `bindEvents` 里加：

```js
window.runtime.EventsOn('panel:invalidate', () => refreshPanel());
```

### 1.4 验证（必须给出这些输出，不许只说"改好了"）

**（a）暴露埋点** —— 新增绑定：

```go
// GetThumbStats 返回缩略图队列统计（诊断用）。
func (a *App) GetThumbStats() string {
	a.mu.RLock(); m := a.manager; a.mu.RUnlock()
	if m == nil { return fail("请先选择 KKS 根目录。") }
	return ok(m.ThumbStats(), "")
}
```

`preview.Stats` 至少含：`generated / memHits / diskHits / misses / failed`。

**（b）验收断言**：

- 选完根目录后立刻调用 `GetThumbStats()`：`misses > 0` 且 3 秒内 `generated > 0`。
- 切到任意含卡片的目录，等 3 秒：右栏格子**全部出图**，`GetThumbStats().generated ≥ 8`。
- 再切回同一目录：`memHits` 或 `diskHits` 增加，`generated` **不增加**（证明缓存生效）。
- `DELCARDS/_state/thumb/` 下出现 `.jpg` 文件。

**（c）失败路径也要可见**：`generateThumb` 出错时 `q.failed++` 并把错误写进日志（`[preview] 生成失败 <path>: <err>`）。**不允许静默丢弃**——否则以后又是一轮"图片不显示但我不知道为什么"。

## 2. FIX-02 卡片焦点：一张大图，不是九宫格（P0）

### 2.1 现象与期望

现状（截图1/2）：点中一张卡，右栏仍显示"此文件夹的卡片 194 张"的 3×n 网格。

期望：**焦点是文件 → 右栏显示这**一**张卡的大预览**（3:4，占满栏宽），下方是它的信息。九宫格只属于"文件夹焦点"。

### 2.2 根因

`BuildPanel` 只做了一件事：把焦点解析成"所在目录"，然后无条件按文件夹构图。没有 `focusKind` 分支。

### 2.3 修法

**（1）入口分支**：

```go
func (m *Manager) BuildPanel(side, mode, rel, focusAbs string) (Panel, error) {
    // ... 定位焦点、算 focusKind ...
    switch focusKind {
    case "card":
        return m.buildCardPanel(panel, focusAbs), nil   // 新增
    case "mod":
        return m.buildZipmodPanel(panel, focusAbs, focusKind), nil
    default:
        return m.buildFolderPanel(panel, focusAbs), nil // 现有逻辑改名
    }
}
```

**（2）`buildCardPanel`**：

```go
// buildCardPanel 单卡片焦点：一张大预览 + 信息。
// 不返回九宫格 —— 九宫格是"文件夹视角"，对单张卡是错误的语义。
func (m *Manager) buildCardPanel(panel Panel, cardAbs string) Panel {
    sec := Section{ID: "preview", Title: "", Layout: "single", Visible: true, Total: 1}
    t := Tile{Kind: "card", Name: filepath.Base(cardAbs), Abs: cardAbs, Rel: m.relOf(cardAbs)}
    t.ThumbKey, t.Thumb, t.Pending = m.requestLargeThumb(cardAbs) // 见 (3)
    t.Selected = true
    sec.Tiles = []Tile{t}
    panel.Sections = []Section{sec}
    panel.Focus.Kind = "card"
    panel.Focus.Name = filepath.Base(cardAbs)
    panel.Focus.Info = m.cardInfoLine(cardAbs)  // "5.7 MB · 依赖 6 个 zipmod"
    return panel
}

// cardInfoLine 信息栏文案：大小 + 依赖数（不再重复文件名，修 FIX-08）
func (m *Manager) cardInfoLine(abs string) string {
    var size int64
    if info, err := os.Stat(abs); err == nil { size = info.Size() }
    deps := len(m.FileDeps[abs])
    return fmt.Sprintf("%s · 依赖 %d 个 zipmod", humanSize(size), deps)
}
```

**（3）大图尺寸类**（九宫格 320×400 撑到 376px 宽会发虚，必须单独一档）：

```go
// internal/preview
type SizeClass string
const (
    SizeGrid  SizeClass = "g"  // 320×400，九宫格
    SizeLarge SizeClass = "l"  // 720×960，单卡预览

```

- 缓存键：`ThumbKey(abs,fp)` 对 grid，`ThumbKey(abs,fp)+"-l"` 对 large。
- 磁盘路径同理加 `-l` 后缀。
- `buildThumbJPEG` 改成 `buildThumbJPEGSized(path, maxW, maxH int)`，`SizeLarge` 传 720/960，质量 85。
- 新增绑定：

```go
// GetBigPreview 单卡大图（720×960）。只查缓存，未命中返回 pending。
func (a *App) GetBigPreview(path string) string
```

**（4）前端新增 `single` 布局**：

```css
.panel-single { padding: 4px 0; }
.panel-single img {
  width: 100%; aspect-ratio: 3/4; object-fit: contain;
  background: #f0f1f3; border-radius: 8px;
}
```

- 未命中大图时：先显示该卡的 320 缩略图（`object-fit: contain` 拉伸，不空白），收到 `thumb:ready`（key 带 `-l`）后替换。
- 大图下方一行：文件名（可换行）+ 信息行。
- 双击大图 → 新窗口/浮层看原图（可选，本轮不做也行，但**不要**再退回九宫格）。

### 2.4 验收

- 点任意一张卡：右栏只出现**一张**大图，无网格、无"还有 N 张"。
- 点文件夹：回到九宫格（A/B 两区规则不变）。
- 点 zipmod：见 FIX-03。
- 大图清晰度：目视不糊（720 宽缩到 376 显示，2x 余量）。

## 3. FIX-03 zipmod：3×n 全显示，不省略（P0）

### 3.1 现象

截图3：`[gyobobo] Claire Set v1.0.zipmod` 被 33 张卡使用，右栏只显示 8 张 + "还有 25 张角色卡"。

### 3.2 根因

`panel.go:300`：

```go
shown, more := tileCount(len(refs))   // 8 + more —— 这是文件夹的规则
```

用户规则：**文件夹预览才省略；zipmod 预览必须全显示**（因为"这个 mod 到底被谁用"需要看全，省略就失去意义）。

### 3.3 修法

**（1）后端：全量，不截断**

```go
// zipmod 的引用卡片：全量返回，不做 8+more 截断。
// 与文件夹九宫格的规则不同（用户明确要求）。
secA.Tiles = make([]Tile, 0, len(refs))
for _, p := range refs {
    secA.Tiles = append(secA.Tiles, Tile{
        Kind: "card", Name: filepath.Base(p), Rel: m.relOf(p), Abs: p,
        ThumbKey: preview.ThumbKey(p, m.fingerprintOf(p)),
        Pending:  true,        // 注意：这里【不】调用 thumbRequest
    })
}
secA.More = 0                   // 永不出现"还有"
secA.Lazy = true                // 新增字段：前端按可视区懒加载
```

**必须同时改的地方**：`Section` 增加 `Lazy bool`。

**（2）为什么不能直接 `thumbRequest` 全量**：500 张引用 = 500 次 `os.Stat` + 500 个队列任务，切换焦点会瞬间打满队列，把真正需要的图挤到后面。所以：

- **文件夹九宫格**（≤9）：后端预请求，一次请求就把图带回来。
- **zipmod 全量列表**：后端只给 `thumbKey`，前端按可视区请求。

**（3）前端懒加载**：

```js
// 只为进入视口的格子请求缩略图，rootMargin 200px 预取一行
const thumbObserver = new IntersectionObserver((entries) => {
    const keys = [];
    entries.forEach(en => {
        if (!en.isIntersecting) return;
        const cell = en.target;
        if (cell.dataset.thumbLoaded === '1') return;
        cell.dataset.thumbLoaded = '1';
        keys.push(cell.dataset.thumbKey);
        thumbObserver.unobserve(cell);
    });
    if (keys.length) requestThumbs(keys);   // 每批 ≤ 12
}, { root: elRightPanel, rootMargin: '200px' });
```

`requestThumbs(keys)` → `GetThumbBatch(keys)` → 拿到后按 key 局部替换 `.thumb` 内容（复用现有 `thumb:ready` 的处理函数，抽成 `applyThumb(key, uri)`）。

（4）**顺序必须稳定**：`sort.Strings(refs)` 之后按"文件名自然序"再排一次（`naturalLess`），否则同一次刷新顺序会跳。

### 3.4 验收

- 33 张引用 → 右栏渲染 **33 个格子**，11 行，**没有**"还有 N 张"。
- 滚动到底，图片在 1 秒内补齐；滚动过程中不卡顿。
- 构造一个 >100 引用的 zipmod，验证：初始只渲染 DOM（骨架），可视区 12 张先出图，滚动续图；`GetThumbStats().generated` 增长应≈可视区数量，而不是全部数量。

## 5. FIX-05 删除毫无反应（P0，最隐蔽）

### 5.1 现象

左侧勾选一张已启用的角色卡 → 点「🗑 删除」→ **什么都不发生**：没有弹窗、没有 toast、没有日志。

### 5.2 根因（已用静态扫描证实）

`frontend/index.html:1642`：

```js
showConfirm('移入回收站',
    `将把 ${items.length} 个项目移入回收站（共 ${formatBytes(plan.totalBytes || 0)}），...`,
    async () => { ... }, '移入回收站');
```

`formatBytes` **在整个项目里不存在**（只有 `formatSize`）。模板字符串在**调用 `showConfirm` 之前**求值 → 抛 `ReferenceError: formatBytes is not defined` → 该异常在 `async doDelete` 内部被 Promise 吞掉（没有 catch）→ 用户侧表现为"点了没反应"。

这也解释了为什么右侧会报"未勾选"（第 4 节）而左侧"完全没反应"：右侧在更早的 `selected.size === 0` 就 return 了，压根没走到这行。

### 5.3 修法（四层，缺一层以后还会复发）

**（1）改函数名**：`formatBytes(...)` → `formatSize(...)`。

**（2）全局异常兜底** —— 任何未捕获错误都必须变成用户可见的弹窗：

```js
window.addEventListener('error', (e) => {
    console.error(e.error || e.message);
    toast('界面发生异常：' + (e.message || '未知错误') + '（详见日志）', 'err');
});
window.addEventListener('unhandledrejection', (e) => {
    const msg = (e.reason && e.reason.message) || String(e.reason);
    console.error(e.reason);
    showAlert('操作未完成：' + msg);
});
```

> 注意：`unhandledrejection` 用 `showAlert`（阻断性），因为异步操作失败用户必须知道；`error` 用 toast，避免循环弹窗。

**（3）所有 `async` 事件处理器统一包 `try/catch`**：

```js
function guard(fn) {
    return async (...args) => {
        try { await fn(...args); }
        catch (err) {
            console.error(err);
            showAlert('操作失败：' + (err && err.message ? err.message : err));
        }
    };
}
document.getElementById('btn-delete').onclick = guard(doDelete);
```

**（4）静态检查纳入例行验证** —— 新增 `tools/check-undefined.mjs`，把本次扫描固化：

```js
// tools/check-undefined.mjs
// 扫描 frontend/index.html 内联脚本，找出"被调用但从未声明"的函数。
// 这条检查能拦住 100% 的 formatBytes 类事故。
import fs from 'node:fs';

const src = fs.readFileSync('frontend/index.html', 'utf8');
const js = src.slice(src.indexOf('<script>'));
const declared = new Set();
for (const m of js.matchAll(/function\s+([A-Za-z_$][\w$]*)/g)) declared.add(m[1]);
for (const m of js.matchAll(/(?:const|let|var)\s+([A-Za-z_$][\w$]*)\s*=/g)) declared.add(m[1]);
const allowed = new Set(['if','for','while','switch','catch','return','typeof','function','new','await',
  'Number','String','Boolean','Array','Object','JSON','Math','Date','Set','Map','parseInt','parseFloat',
  'isNaN','isFinite','setTimeout','clearTimeout','setInterval','clearInterval','requestAnimationFrame',
  'fetch','Error','Promise','document','window','console','Image','URL','Blob','FileReader',
  'ResizeObserver','IntersectionObserver','structuredClone','crypto']);
const calls = new Set();
for (const m of js.matchAll(/(?<![.\w$])([a-zA-Z_$][\w$]*)\s*\(/g)) calls.add(m[1]);
const bad = [...calls].filter(n => !declared.has(n) && !allowed.has(n) && !/^[A-Z]/.test(n) && n !== 'async' && n !== 'var');
if (bad.length) { console.error('未定义函数：', bad.join(', ')); process.exit(1); }
console.log('OK：无未定义函数调用');
```

挂到验证命令里：`node tools/check-undefined.mjs && go test ./...`。

## 6. FIX-06 列表混入非卡片文件（P1）

### 6.1 现象

截图1 左列出现 `Cache_4379b653c5a27864.jpg`、`Cache_4175e3ce77527a70.jpeg`、`Halo.ppk` 等 —— 这些不是角色卡。

### 6.2 根因

`app.go:587` 起的 `buildTreeLocked` 中：

```go
guids := m.depsFor(path, isDel)
...
nodes = append(nodes, TreeNode{ Type: "card", ... })
```

只判断了 `info.IsDir()`，**没有判断扩展名**。目录下任何文件都会被当成 `card` 节点。

危害不止是"列表难看"：
- 隔离时会对 `.jpg` 调用依赖解析（白费 IO）；
- 全选 + 隔离会把这些文件一起移走（用户根本没想动它们）；
- 面板说"194 张卡片"而列表有 200 行，数字对不上。

### 6.3 修法

给 `buildTreeLocked` 传入资源类型，按扩展名过滤：

```go
// 改动前：buildTreeLocked(root string, isDel bool)
// 改动后：buildTreeLocked(root string, isDel bool, kind ResourceKind)

if !info.IsDir() {
    if !strings.EqualFold(filepath.Ext(path), kind.FileExt) {
        return nil          // 不是本类型的资源文件，直接跳过
    }
    ...
}
```

调用方（`GetLeftTreeData` / `GetRightTreeData`）从 `mode` 取 `KindByMode(mode)` 后传入。`GetInvisibleTreeData` / 回收站分支不走这个函数，不受影响。

> `buildModsTree` 请一并检查是否按 `.zipmod` 过滤；若没有，同样补上。

### 6.4 验收

- 在 `coordinate/female` 放一个 `.jpg`：列表**不显示**它，面板卡片数 = 列表行数。
- 全选隔离：`.jpg` 原地不动（可加一条日志 `跳过非资源文件 N 个`）。

## 7. FIX-07 回收站丢失目录结构（P1）

### 7.1 现象

`DELED/female_card/` 下所有卡平铺在一层。删两个不同子目录里的同名 `2.png` 会变成 `2.png` / `2__2.png`，用户在回收站里完全看不出原本在哪。

### 7.2 根因

`internal/ops/crud.go:180-183`：

```go
if !info.IsDir() {
    // 单文件直接放 spec 目录下；重名加 __2
    trashAbs = s.UniqueTrashPath(spec, name)
}
```

只用了 `name`，丢掉了相对路径。

### 7.3 修法

`PlanDelete` 的 `specOf` 回调改为返回 `(spec, root, ok)`，用 `root` 算相对路径：

```go
type SpecFunc func(abs string) (spec string, root string, ok bool)

rel, err := filepath.Rel(root, abs)
if err != nil || strings.HasPrefix(rel, "..") {
    rel = filepath.Base(abs)
}
trashAbs := filepath.Join(s.SpecDir(spec), filepath.FromSlash(rel))
if exists(trashAbs) {
    trashAbs = uniqueSuffix(trashAbs)   // 只在这种真冲突时才加 __2
}
```

`_trash.json` 里的 `OriginalAbs` 保留不变（还原仍按它走，不受影响）。

### 7.4 验收

- 删 `female/22.7.27/2.png` → 出现 `DELED/female_card/22.7.27/2.png`。
- 删 `female/22.7.28/2.png` → 两个文件**互不冲突**，各自在自己的子目录。
- 还原两条 → 都回到原位，`_trash.json` 对应条目被清除。

## 9. 右栏三态总规范（把 FIX-02/03 合并成一张决策表，实现时照此）

| 焦点类型 | 区域 A | 区域 B | 布局 | 是否省略 | 缩略图请求方式 |
|---|---|---|---|---|---|
| **文件夹** | 直接子文件夹（封面 + 名称 + N 个文件） | 直接子卡片 | `grid` 3 列 | **8 + "还有 N"**（n>9） | 后端预请求（≤16 张） |
| **卡片** | —（不渲染区域 A） | 该卡**单张大图** | `single` | 不适用 | `GetBigPreview`（720×960） |
| **zipmod** | 引用它的卡片 | 引用它的 DLL（`list`） | `grid` 3 列 | **全显示，永不省略** | 前端按可视区懒加载 |
| **隐藏项 / 回收站** | 不渲染 | 不渲染 | — | — | — |

三条不许违反的推论：

1. 卡片焦点如果出现九宫格 → 错（FIX-02）。
2. zipmod 焦点如果出现"还有 N 张" → 错（FIX-03）。
3. 文件夹焦点如果卡片全显示不省略 → 也错（会把 194 张全铺开，滚动到崩溃）。

> 判断口诀：**"文件夹是概览，要省略；zipmod 是审计，要全量；单张卡是查看，要大图。"**
