### 5.2 扫描流程

## 6. 阶段 4：重写文件夹迁移引擎（本次最核心）

### 6.1 缺陷根因（三条，缺一不可）

| # | 根因 | 表现 |
|---|---|---|
| **B1** | 文件夹分支用 `collectFilesStrict(src, core.IsCardFile)` 只收卡片文件；**结果为 0 时被当成"空文件夹"**，走 `os.MkdirAll(dstDir)` 并计为成功 | 内容一个没搬，DEL 区却出现空目录 →「只生成文件夹结构」 |
| **B2** | 非卡片文件（`.txt`、`.zipmod`、`.bak`、子目录里的其它资源）**根本不进计划** | 用户说的"不转移整个文件夹的所有内容" |
| **B3** | 执行时先 `ensureTargetParent()` 建目录、再逐文件移动；一旦有冲突/失败 → 回滚只回滚**文件**，不回滚**目录** | 失败后残留空目录树，看起来"结构生成了但内容是空的" |

另外：源侧迁移完成后**从不清理源目录的空壳**，隔离完原目录留下一堆空文件夹。

### 6.2 新模型：先算清、再动盘

新增 `transfer.go`（与 `manager.go` 同级），定义：

```go
type StepOp int
const (
    OpMkdir StepOp = iota // 建目录（含空目录，保留结构）
    OpMove                // 移动文件
    OpRmdir               // 清理源侧空目录（自底向上，仅空目录）
)

type TransferStep struct {
    Op   StepOp
    Src  string // OpMkdir/OpRmdir 时为空
    Dst  string
    Size int64
}

type Conflict struct {
    Src    string
    Dst    string
    Reason string // "目标已存在同名文件" / "目标已存在同名目录"
}

type TransferPlan struct {
    Steps     []TransferStep // 顺序：先全部 OpMkdir（父先子后）→ OpMove → OpRmdir（子先父后）
    Files     int
    Dirs      int
    Bytes     int64
    Conflicts []Conflict
    Skipped   []string // 符号链接等不处理的项
}
```

### 6.3 规划函数（纯只读，绝不落盘）

```go
// planFolderTransfer 生成"把 srcDir 整棵子树迁移到 dstDir"的完整计划。
// 只读：只做 Walk + Stat，不创建、不移动、不删除任何东西。
func (m *Manager) planFolderTransfer(srcDir, dstDir string) (*TransferPlan, error)
```

规则（**逐条实现，不许漏**）：

1. `filepath.WalkDir(srcDir)`，**不过滤扩展名** —— 目录内**所有普通文件**都迁；
2. 跳过符号链接（记入 `Skipped`，日志 warn 一行）；
3. **每一个目录（含空目录）**都生成一条 `OpMkdir`，父目录排在子目录之前；
4. 每个文件生成一条 `OpMove`，同时 `os.Stat` 记录 `Size`；
5. 目标侧已存在同名文件/目录 → 记入 `Conflicts`，**不中断 Walk**（要一次把所有冲突报全）；
6. 若 `Files == 0 && Dirs == 1`（即空文件夹本身）→ 返回 `errEmptyFolder`，**不生成任何 Step**；
7. 规划阶段记录的每个文件 `size + mtime` 存入内存，执行前逐条复核（防规划后被外部改动）。

> 同一个规划函数同时服务三个入口：`Isolate`（KKS → DEL）、`Restore`（DEL → KKS）、`Paste`（任意方向）。
> **禁止**为三个入口各写一份 Walk 逻辑 —— 这是当初 B1/B2/B3 三处不一致的来源。

### 6.4 执行函数

```go
// execTransferPlan 按计划执行，全部成功或全部回滚。
// 每一步都通过 tx.Tx 记录，崩溃可由启动恢复流程回滚。
func (m *Manager) execTransferPlan(txn *tx.Tx, plan *TransferPlan, onLog func(level, msg string)) (moved, dirs, dirsRemoved int, err error)
```

执行顺序与失败语义：

1. **冲突预检**：`len(plan.Conflicts) > 0` → 立即返回 `errConflicts`，**一个字节都不动**；
2. `OpMkdir`：`os.MkdirAll`，并在事务里记为"创建目录"步骤；
3. `OpMove`：调 `m.txMove(txn, src, dst)`（已有），失败即整体中止；
4. `OpRmdir`：自底向上删**空**目录（`os.Remove`，非空则跳过），事务记为"删除目录"步骤；
5. 任一步失败 → `txn.Rollback()`，回滚顺序：文件的逆序移回 → 目录的逆序 `Remove`（仅空目录）；
6. 回滚自身失败 → 保留 journal 文件，日志输出 `[严重] 回滚未完成，请检查 <清单>`，并把 `failed=false` 之外的项全部列出来（不允许"静默当成功"）。

**`tx.Tx` 需要扩展**：新增 `KindMkdir` / `KindRmdir` 两种 step 类型 —— 现有实现只有文件移动，这是 B3 的根因。

### 6.5 冲突的产品行为

默认 **整批中止**，弹窗必须说清楚，不能只写日志：

```
标题：无法迁移，目标位置已存在同名文件
正文：共 37 个冲突，以下为前 10 个：
      DEL-female_card/22.7.15/a.png
      ...
操作：未对你的文件做任何改动。
     [取消]  [跳过已存在项，继续迁移其余 12 个]
```

选"跳过"时，被跳过的项计入 `Skipped`，剩余项照常迁移，结果日志给出 `跳过 37，迁移 12`。

### 6.6 不变量（写成 `assert` + 单测，缺一不可）

| 编号 | 不变量 |
|---|---|
| **I1** | 规划阶段零副作用：调用 `planFolderTransfer` 后源目录与目标目录的 `os.Stat` 结果完全不变 |
| **I2** | 执行成功当且仅当：`moved == plan.Files && dirs == plan.Dirs` |
| **I3** | 失败后：源侧文件数 = 操作前文件数；目标侧**不留任何新建目录** |
| **I4** | 迁移成功后：源侧该子树内文件数为 0，且空目录被清理（父目录保留） |
| **I5** | 目标侧文件数（递归）= 源侧迁移前文件数（递归），逐字节大小合计相等 |
| **I6** | 同一文件夹重复隔离 → 全部命中 `Conflicts` → 返回"已存在"而不是"失败"，且不动盘 |

### 6.7 错误文案表（前端直接展示，不许自造）

| 场景 | 文案 |
|---|---|
| 空文件夹 | `「%s」是空文件夹，没有可迁移的内容。` |
| 全部冲突 | `目标位置已存在 %d 个同名文件，未做任何改动。` |
| 部分失败 | `迁移中断，已回滚到操作前状态（失败：%s）。` |
| 回滚失败 | `回滚未完成，以下文件需要你手动检查：%s` |

### 6.8 必写单测（`transfer_test.go`）

| 用例 | 断言 |
|---|---|
| T1 单层：3 卡 + 子目录 2 卡 | 5 条 Move；DEL 侧目录结构与源一致；I5 成立 |
| T2 空子目录 | 保留空子目录，`Dirs` 计数正确 |
| T3 混合内容（`.png` + `.txt` + `.zipmod` + `.bak`） | **全部 4 个文件都被迁走**（B2 回归） |
| T4 目标冲突 | `Steps` 非空但执行后零改动；返回冲突数正确（I3） |
| T5 中途失败注入（把目标文件设为只读/加锁） | 回滚后源文件数不变、DEL 无空目录残留（I3） |
| T6 重复隔离 | 返回"已存在"，`Success=true`，不动盘（I6） |
| T7 多选 3 个互不包含的文件夹 | 合并为一个事务，事务 steps 总数 = 三个计划之和 |
| T8 多选父子重叠（A 与 A/B） | 去重后只迁 A，A/B 只被处理一次 |
| T9 空文件夹 | 返回 `errEmptyFolder`，DEL 侧不产生目录（B1 回归） |

> T9 是本次最关键的一条：**它必须能复现用户遇到的"只生成文件夹结构"**。先写测试让它红，再改代码让它绿。

### 6.9 顺带修掉的两个同源问题

1. **源侧空壳**：迁移后源目录留空文件夹 → 由 `OpRmdir` 步骤解决（仅删空目录，非空绝不删）。
2. **`Isolate`/`Restore`/`Paste` 三套 Walk 逻辑**：全部收敛到 `planFolderTransfer`，只保留"方向"不同。

## 9. 自检脚本 `tools/check-undefined.mjs`

若文件不存在，创建它（放在 `tools/`，不要放根目录）：

```js
// 静态扫描 index.html 内联 JS 里"调用了但从未定义"的函数名。
// 这类错误会被 async 函数吞掉，表现为"点了没反应"，人工点击查不出来。
import fs from 'fs';
const src = fs.readFileSync(new URL('../frontend/index.html', import.meta.url), 'utf8');
const js = src.slice(src.indexOf('<script>'));
const declared = new Set();
for (const m of js.matchAll(/function\s+([A-Za-z_$][\w$]*)/g)) declared.add(m[1]);
for (const m of js.matchAll(/(?:const|let|var)\s+([A-Za-z_$][\w$]*)\s*=/g)) declared.add(m[1]);
const builtin = new Set(['if','for','while','switch','catch','return','typeof','function','new','await',
  'Number','String','Boolean','Array','Object','JSON','Math','Date','Set','Map','parseInt','parseFloat',
  'isNaN','encodeURIComponent','setTimeout','clearTimeout','setInterval','clearInterval','alert','confirm',
  'Error','Promise','document','window','console','requestAnimationFrame','fetch','Uint8Array','Image','URL']);
const missing = [...new Set([...js.matchAll(/(?<![.\w$])([a-zA-Z_$][\w$]*)\s*\(/g)].map(m => m[1]))]
  .filter(n => !declared.has(n) && !builtin.has(n) && !/^[A-Z]/.test(n)).sort();
console.log('undefined:', missing.length ? missing.join(', ') : '(none)');
process.exit(missing.length ? 1 : 0);
```

## 10. 反模式黑名单（看到自己这么写就立刻停手）

| 反模式 | 为什么错 |
|---|---|
| `if len(files) == 0 { os.MkdirAll(...) }` 然后 `success` | 把"没找到"当"空文件夹"，用户看到的就是"只建了结构" |
| 边 Walk 边移动 | 失败无法回滚，只能靠人工收拾 |
| 用 `collectFilesStrict(..., IsCardFile)` 迁文件夹 | 非卡片文件被静默丢弃（B2） |
| 先建目录再检查冲突 | 失败残留空目录树（B3） |
| 给三个入口各写一份 Walk | 三份逻辑迟早不一致，改一处漏两处 |
| `//go:build ignore` 掉待删文件 | 违反 R2，`grep` 依然命中，后人以为还有这功能 |
| 为了"兼容"保留 `GlobalDepMap` | 没有消费方的数据结构就是技术债，扫描还要为它解析全部卡片 |
| 每次操作重新扫盘 | 违反 R4，4531 mods + 16150 卡时代价不可接受 |
