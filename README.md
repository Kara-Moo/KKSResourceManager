# KKS 资源管理器 · KKS Resource Manager

> 面向 **Koikatsu Sunshine（KKS）** 的资源安全管理桌面工具。
> 目标只有一句话：**安全地隔离无用资源，绝对不破坏原有目录结构。**

> **v2.4 状态（2026-11-14）**：已彻底移除 zipmod 管理能力；索引升级为 schema v2
> （只存卡片指纹，不解析 PNG / GUID）；文件夹迁移引擎重写为先规划后动盘、整树迁移、失败可回滚。

## 1. 它解决什么问题

KKS 的角色卡、场景卡、服装卡都是 PNG 文件，但它们在 PNG 尾部数据里记录了所依赖的 **zipmod GUID**。一个典型的游戏目录往往有：

- 上万张卡片、数千个 zipmod；
- 一个 zipmod 可能被几十到几千张卡引用；
- 还有一部分 BepInEx 插件（DLL）在代码里**硬编码**了 zipmod GUID。

于是「清理不用的资源」变成一件高风险的事：

| 常见做法 | 后果 |
|---|---|
| 手动删除不喜欢的卡片 | 不知道这张卡依赖哪些 mod，留下大量无人使用却不敢删的 zipmod |
| 直接删 zipmod | 引用它的卡片进游戏后报错、服装缺失；硬编码引用它的插件可能直接崩溃 |
| 把卡片整文件夹拖走 | 原始目录结构被破坏，日后无法还原 |

本工具的做法是：**先建立全局依赖图，再决定什么能移走**。所有移动都进入游戏目录旁边的隔离区（而不是删除），并保留原始相对路径；每次写操作都进事务 journal，可以撤销，进程被杀也能在下次启动时自动回滚。

## 2. 核心概念

| 概念 | 说明 |
|---|---|
| `KKS_ROOT` | 游戏根目录，例如 `E:\KKV114`。首次启动时由用户选择 |
| `DELCARDS_ROOT` | 隔离区根目录，固定为 `KKS_ROOT/../DELCARDS`。**游戏目录内只发生"移动资源"，所有状态文件都写在隔离区** |
| 资源类型 | 女卡 / 男卡 / 场景 / POSE / 女装 / 男装，共 6 类；支持 `.png` / `.jpg` / `.jpeg`（大小写不敏感） |
| zipmod | `mods/` 下的 `.zipmod` 文件（本质是 zip，内含 `manifest.xml` 提供 GUID） |
| GUID | zipmod 的唯一标识，例如 `com.DeathWeasel.AccessoryHairBack`、`moderchan.CharamakerSupportMOD` |
| `GlobalDepMap` | `GUID → 引用它的资源文件绝对路径列表`，由索引正向数据派生，**不落盘** |
| 隔离 | 把勾选的资源从 `KKS_ROOT` 移到 `DELCARDS/DEL-xxx`，保留相对目录结构 |
| 启用 / 恢复 | 把隔离区的文件放回**原始绝对路径**（父目录不存在则重建） |
| 三道防线 | 判定 zipmod 能否移出的唯一规则集：无卡片引用 ∧ 无插件硬编码引用 ∧ 无其它 zipmod 依赖 |
| 事务 / journal | 每个写操作的意图先落盘再执行；崩溃可恢复、成功可撤销 |

### 资源类型与目录映射

| 模式 | 中文名 | 游戏内路径（相对 `KKS_ROOT`） | 隔离目录（相对 `DELCARDS`） |
|---|---|---|---|
| `female_card` | 角色卡（女） | `UserData/chara/female` | `DEL-female_card` |
| `male_card` | 角色卡（男） | `UserData/chara/male` | `DEL-male_card` |
| `scene` | 场景卡 | `UserData/Studio/scene` | `DEL-scene` |
| `pose` | POSE 动作 | `UserData/Studio/pose` | `DEL-pose` |
| `coord_f` | 女性服装 | `UserData/coordinate/female` | `DEL-coord_f` |
| `coord_m` | 男性服装 | `UserData/coordinate/male` | `DEL-coord_m` |
| `zipmod` | Zipmod | `mods` | `DEL-zipmod` |

> 工作室角色 `UserData/Studio/character` 不参与扫描，也不创建隔离目录。
> zipmod 的隔离目录是扁平的（`DEL-zipmod/文件名`），其余 6 类保留完整子目录层级。

## 3. 功能总览

### 3.1 扫描与依赖索引

- 启动时选择 `KKS_ROOT`，后台异步全量扫描，界面实时显示进度
- 扫描 6 类资源 + zipmod + `BepInEx/plugins`、`BepInEx/core` 下的 DLL
- 建立**正向索引**（每个文件依赖哪些 GUID），反向 `GlobalDepMap` 一律现算，避免双写不一致
- 增量扫描：以 `size + mtime` 作指纹，未变文件零 IO 复用；变更文件并行解析（worker ≤ 8）
- 本地缺失的 GUID 会被列出，供「修复缺失 zipmod」使用
- **JPG 角色卡支持**：`.jpg` / `.jpeg` 与 PNG 一样进入列表、统计、索引、预览与依赖图；
  卡片数据按「PNG 取 IEND 之后 / JPEG 取 EOI 之后」统一提取，复用同一套 zipmod 解析逻辑

### 3.2 安全加载隔离模式（默认）

- 双栏浏览：左＝游戏目录（已启用），右＝隔离区（已停用）
- 勾选 → 「确认隔离」/「恢复启用」，批量移动
- **自动连带处理 zipmod**：只有在「移除本次勾选文件的引用后彻底无人引用」时，才把对应 zipmod 一并隔离；只要还有任一未勾选文件引用它，就原地保留
- 复制 / 剪切 / 粘贴，语义对齐 Windows 资源管理器；zipmod 的粘贴等价于启用 / 隔离并同样走三道防线
- 隐藏空文件夹：把空目录从列表中隐藏（**不是删除**），可通过「隐藏的文件夹」模式恢复；隔离前会依据隐藏索引重建父路径
  只有真正的空文件夹才显示隐藏入口（列表按钮与右键菜单判定一致），不会出现「点了才提示不是空文件夹」

### 3.3 自由修改模式

- 新建文件夹（自动避让重名，创建后立即进入行内重命名）
- 重命名（行内编辑，回车提交 / Esc 保留原名）
- 删除 → **移入回收站**（可还原，不是真删）
- 回收站模式：浏览、还原、彻底删除（需输入名称二次确认）
- 空白区域右键 → 目录菜单（粘贴 / 新建文件夹 / 全选 / 刷新 / 在资源管理器中打开当前目录）
- 行右键菜单 → 「在文件资源管理器中打开」：文件夹打开自身，文件打开父目录并选中该文件
- 名称校验：非法字符、结尾空格或点、长度上限 100、Windows 保留名（`CON`/`PRN`/`NUL`/`COM1-9`…）、同目录重名（不区分大小写）

### 3.4 zipmod 管理

- zipmod 列表第三列显示**红色占用数**（被多少卡片 + 插件引用），0 时灰色
- 点击占用数 → 详情弹窗：引用它的卡片清单、硬编码引用它的 DLL 清单（含命中方式）
- **修复缺失 zipmod**：两阶段计划，区分「可从隔离区/回收站放回」与「本地不存在、需重新下载」
- **隔离多余 zipmod**：两阶段计划，候选默认全选；「永不自动隔离」清单逐项给出原因（例如被 `Timeline.dll` 硬编码引用）

### 3.5 预览、历史与日志

- 右栏双窗格预览（详见第 7 节）
- 缩略图两级缓存 + 后台 3 worker 队列，UI 请求路径**绝不解码 PNG**
- 操作记录窗口：时间 / 操作名 / 影响项数 / 状态 / 撤销按钮，筛选「全部 / 可撤销 / 已撤销」
- 运行日志窗口：级别筛选、搜索、复制、导出；日志来自后端 5000 条环形缓冲

## 5. 两种工作模式

| | 安全加载隔离模式（默认） | 自由修改模式 |
|---|---|---|
| 定位 | 只做「隔离 / 启用」，绝不修改文件名与目录 | 允许新建 / 重命名 / 删除 |
| 新建 / 重命名 / 删除入口 | **完全不渲染** | 显示 |
| zipmod 判定 | 强制走三道防线 | 强制走三道防线 |
| 删除行为 | 无删除入口 | 移入回收站，可还原 |
| 撤销 | 支持 | 支持 |

「管理类型」下拉共 9 项：6 类资源、`Zipmod`、`隐藏的文件夹`、`回收站 (DELED)`。后两者为只读浏览 / 管理视图，隔离与启用按钮在其中禁用。

## 6. 安全设计（最重要）

### 6.1 三道防线：zipmod 隔离的唯一判定入口

```
一个 zipmod 可以被移出 mods，当且仅当：
  ① 没有任何（未被本次操作移走的）资源卡片引用它   ← GlobalDepMap
  ② 没有任何 BepInEx 插件硬编码引用它              ← PluginDepMap
  ③ 没有任何其它 zipmod 在 manifest 里声明依赖它    ← ModDeps
```

`guard.go` 的 `IsZipmodSafeToMoveEx` 是**唯一**判定入口，`Isolate` / `Paste` /「一键隔离多余 zipmod」都必须调用它，禁止各写一份检查逻辑。所有判定只读内存索引，绝不扫盘。无法识别 GUID 的 zipmod 一律保守拒绝移出。

### 6.2 事务与崩溃恢复

- 每个 `Move / Copy / Mkdir / Rename / Trash` 的**第一步**就把整个事务的 intent 写盘并 `Sync`，然后才执行
- journal：`DELCARDS/_journal/<txId>/journal.json`，`txId` 形如 `20261113-180233-a3f2`，字典序即时间序
- 步骤状态 `intent → done`；进程被杀后，下次启动扫描未提交 journal 并自动回滚
- 回滚规则：`move` 移回、`copy` 删副本、`mkdir` 删空目录、`rename` 改回原名、`trash` 移回原位
- 冲突时移到 `src.conflict-<txid>` 并明确报出「哪一步、哪个文件」
- 撤销前逐步校验文件指纹（`size + mtime`），外部改过就拒绝整个撤销
- 单事务步数上限 500，历史保留最近 200 条

### 6.3 删除只进回收站

- 删除 = 移动到 `DELCARDS/DELED/<种类>/<原相对路径>`，**保留子目录结构**
- `DELED/_trash.json` 记录 `OriginalAbs`（zipmod 在 `mods/sub/` 下时尤其关键），还原按它回到原位
- 唯一允许真删的地方是回收站「彻底删除」，且需输入名称二次确认
- 资源文件永不 `os.RemoveAll`

### 6.4 目录结构不破坏

- 隔离 `female/22.7.27/card.png` → `DEL-female_card/22.7.27/card.png`，先建目标目录再移动
- **源目录即使变空也绝不删除**
- 恢复时按原始绝对路径放回，父目录不存在则重建
- 隐藏空文件夹会记录原始目录树，隔离前依据它重建父路径

### 6.5 其它保护

- 跨盘移动：先查目标盘剩余空间（`GetDiskFreeSpaceEx`），复制后校验大小再删源；删源失败会删除目标副本回滚，不留双份
- 绝不覆盖已存在目标：`O_EXCL` / 预检同名冲突，冲突一次性全部收集后展示
- 路径白名单：所有预览 / 打开目录操作都校验路径必须位于受管范围内
- 全局异常兜底：`window.onerror` → toast，`unhandledrejection` → 阻断性弹窗；所有异步事件处理器经 `guard()` 包裹。**任何一处 JS 错误都必须让用户看见**，不允许退化成「点了没反应」
- 静态检查 `tools/check-undefined.mjs` 扫描「被调用但从未声明」的函数，防止同类静默故障复发

## 7. 右栏预览的三种状态

判断口诀：**文件夹是概览，要省略；zipmod 是审计，要全量；单张卡是查看，要大图。**

| 焦点类型 | 区域 A | 区域 B | 布局 | 是否省略 | 缩略图策略 |
|---|---|---|---|---|---|
| **文件夹** | 直接子文件夹（封面 + 名称 + N 个文件） | 直接子卡片 | 3 列九宫格 | `n>9` → 8 格 +「还有 N」 | 后端预请求 ≤16 张 |
| **卡片** | 不渲染 | 该卡单张大图 | `single`（3:4，满栏宽） | 不适用 | `GetBigPreview`（720×960 档） |
| **zipmod** | 引用它的卡片（含 PNG / JPG） | 「被 N 个 dll 插件使用」文字说明 | 3 列九宫格 | **全显示，永不省略** | 前端按可视区懒加载 |
| 隐藏项 / 回收站 | 不渲染 | 不渲染 | — | — | — |

- 缩略图两档缓存：`SizeGrid` = 320×400（键 `sha1(abs|size|mtime)`）、`SizeLarge` = 720×960（键加 `-l` 后缀，磁盘文件也独立）
- 未就绪时先显示骨架格；大图未就绪时先用 320 档占位（`object-fit: contain`，不裁切）
- 生成完成经 `thumb:ready` 批量事件推送，前端按 `thumbKey` **局部替换 `<img src>`**，不重渲染整个面板
- zipmod 全量列表用 `IntersectionObserver`（`rootMargin: 200px` 预取一行）按可视区请求，每批 ≤12 张，避免 2000 张引用瞬间打满队列

## 8. 性能与缓存

| 环节 | 做法 |
|---|---|
| 索引 | `DELCARDS/_state/index.json` 原子写（`.tmp → Sync → Rename`）；只存正向数据，反向图启动时 `derive()` 现算 |
| 增量扫描 | `size + mtime` 指纹 diff，未变文件零 IO；变更文件并行解析（worker ≤ 8） |
| 文件夹统计 | 一次后序遍历聚合，替代「每个文件夹递归遍历整棵树」的 O(n²) |
| GUI 判定 | 依赖判定全部走内存索引，不做 `os.Stat` |
| 缩略图 | 内存 LRU 256 + 磁盘 sha1 分片；3 worker 有界队列、去重、优先级、100ms 批量通知 |
| DLL 指纹 | 按指纹缓存，GUID 集合不变则不重扫 DLL |
| 目录快照 | LRU 128，目录 mtime 变化才失效 |

**真实目录实测**（`E:\KKV114`，约 20,800 个文件、4,531 个 zipmod、16,150 张卡片）：

| 场景 | 结果 |
|---|---|
| 冷启动全量扫描 | 25–27 s |
| 热启动（无变更） | **约 0.22–0.24 s**，解析 0 个，复用 20,831 条 |
| 根目录面板构建 | 约 69 ms |
| zipmod 全量 2,131 个引用面板 | 约 28–44 ms |
| 缩略图 | 冷启动 8 张 3 秒内出齐、失败 0；重启后 `diskHits=8` 且 `generated` 不增长；单张约 21 KB |
| 大图 vs 九宫格 | 687×960 / 166 KB vs 286×400 / 36 KB |

> 热启动从改造前的 3–15 分钟降到约 0.22 秒，是最主要的性能收益。

```
│   ├── DELinvisible.json
│   ├── OriginKKS.json
│   └── OriginDEL.json
├── DELED/                  # 回收站
│   ├── <种类>/<原相对路径>
│   └── _trash.json
├── _state/
│   ├── index.json          # 持久化索引（正向数据）
│   ├── history.json        # 操作历史（最近 200 条）
│   └── thumb/<分片>/*.jpg  # 缩略图磁盘缓存（含 -l 大图档）
└── _journal/<txId>/
    └── journal.json        # 未完成事务（启动自动回滚后清理）
```

`index.json` 结构版本 `SchemaVersion = 1`；版本不符 / 文件损坏时自动丢弃并全量重建，不会阻断启动。

## 10. 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│ frontend/index.html  原生 HTML/CSS/JS（3224 行，无构建步骤）  │
│  事件委托 · 模态对话框 · IntersectionObserver · 局部补图      │
└───────────────────────────┬─────────────────────────────────┘
                            │ Wails 绑定（51 个 App 方法，JSON 字符串）
┌───────────────────────────┴─────────────────────────────────┐
│ app.go         绑定层 / 响应封装 / 事件推送 / 日志环形缓冲    │
│ manager.go     核心状态机：隔离、恢复、剪贴板、扫描编排        │
│ panel.go       右栏面板三种焦点构图                           │
│ parser.go      PNG 尾部 / manifest.xml 二进制解析              │
│ preview.go     图像解码、缩放、JPEG 编码                       │
│ guard.go       zipmod 三道防线唯一入口                        │
│ crudops.go / zipmodops.go / thumbs.go / logring.go ...        │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────┴─────────────────────────────────┐
│ internal/                                                    │
│  index/    持久化索引、增量扫描、派生反向图                   │
│  core/     自然序比较、目录快照、封面缓存                     │
│  preview/  缩略图两级缓存 + 有界并发队列 + 尺寸档             │
│  plugin/   DLL 硬编码 GUID 扫描、三道防线判定                 │
│  tx/       事务 journal、崩溃恢复、操作历史与撤销              │
│  ops/      回收站、新建/重命名/删除/还原                       │
│  fsx/      Windows 文件名校验                                 │
└─────────────────────────────────────────────────────────────┘
```

**分层原则**：`internal/` 各包不依赖 Wails，可独立单元测试；`app.go` 是唯一绑定层；前端只发请求和渲染，不自行拼装业务状态。

**关键设计决策**

1. **单一真源**：反向依赖图永远由正向数据现算（`derive.go`），不落盘、不增量 `append`。历史上增量维护导致同一文件移动 N 次后积累 N 条重复引用，进而让 zipmod 判定失真。
2. **UI 请求路径禁止解码 PNG**：一次九宫格 9 张卡，每张可能 40 MB，同步解码会冻结界面 5–15 秒。解码只发生在后台 worker。
3. **赋值与启动同一入口**：`App.attachManager` 是唯一设置 `a.manager` 并启动缩略图队列的地方，避免「startup 时 manager 还是 nil」这类两段代码各自合理、合起来失效的问题。

## 11. 依赖解析原理

| 来源 | 做法 |
|---|---|
| **卡片 PNG** | 复用 `github.com/GenesisAN/illusionsCard` 读取 PNG 尾部数据 → `ReadCard` → `GetZipmodsDependencies()`；场景卡额外提取 `SceneExtended.itemInfo`；兜底用 msgpack 解码器在尾部数据中定位 `UniversalAutoResolver` 写入的依赖条目 |
| **zipmod** | 打开 zip 找 `manifest.xml`，解析 `guid`；兼容 UTF-16 → UTF-8 转码与畸形 XML 的「移除多余闭合标签」修补；尽力提取 `<dependencies>` / `<dependency>` 声明的 mod 间依赖 |
| **BepInEx 插件** | 读取 DLL 字节，对每个 GUID 同时做 UTF-8 与 UTF-16LE 的 `bytes.Contains` 匹配；GUID 长度 < 8 过滤以减少误判；单文件 > 128 MB 跳过；按指纹缓存 |

> 二进制解析能力移植自参考项目 `GenesisAN/KKCardModCheck`，未从零手写。

## 15. 已知限制与注意事项

- **仅支持 Windows**：磁盘空间检查使用 `GetDiskFreeSpaceEx`，其它平台有占位实现；界面依赖 WebView2。
- **首次使用务必备份**：工具会移动真实文件。虽然所有操作可撤销、可还原，仍建议先备份 `UserData` 与 `mods`。
- **不要与其它 mod 管理器同时改动同一目录**：索引以 `size + mtime` 为指纹，外部程序在扫描后修改文件可能导致判定基于旧数据；改动后请点「重新扫描」。
- **菜单中的 `Ctrl+V` / `Ctrl+A` / `F5` / `Ctrl+Shift+N` 目前是提示文字，尚未全局绑定键盘快捷键**。已实现的键：`Esc` 关闭弹窗、列表内 `Space` 切换勾选、行内重命名 `Enter`/`Esc`。
- **不含 KKS 附加数据的纯 JPG 图片，zipmod 依赖数客观为 0**：工具会把它当作卡片显示、预览并纳入统计，信息栏如实写「依赖 0 个 zipmod」，不会伪造依赖。真正携带 KKS 尾部数据的 JPG 会解析出与 PNG 相同的 GUID 列表。
- **zipmod 隔离区是扁平的**：`DEL-zipmod` 不保留 `mods/` 内的子目录层级；还原依赖 `index.json` 里的 `OriginRel` 与回收站的 `OriginalAbs`。请勿手工整理该目录。
- **「修复缺失 zipmod」只能找回本地已有文件**：隔离区和回收站里都没有的 GUID 会列为「无法修复」，需要重新下载原 mod。
- 前端目前是单文件 `index.html`（约 3200 行），未拆成模块。
- 索引的 `SchemaVersion` 变更会触发一次全量重建（约 25 s），属预期行为。
